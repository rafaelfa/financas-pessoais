## 2. Valor inválido

**Zero** — no diálogo de edição, `0` e «Guardar alterações»:

```
erro no campo: "O valor não pode ser zero."
diálogo aberto: sim      HTTP: 200 (resposta da action com ok:false)
```

A escrita está atrás de `if (!parsed.success) return`, e o schema recusa antes de qualquer
`update` (medido isoladamente, sem servidor):

```
$ node schema-check.mjs
0 RECUSADO: O valor não pode ser zero.
-500 ACEITE
5555 ACEITE
```

**Negativo** — digitei `-5,00` e gravei: **aceite**, sem mensagem e sem 500; a base
passou de `-5555` para `-500` cêntimos. O schema aceita magnitudes negativas
(`-999_999_999_99 .. 999_999_999_99`) e o diálogo aplica o sinal do `kind`; o resultado
(`EXPENSE -500`) é coerente com «uma despesa de 5,00 €», mas o texto do campo diz
«Escreve o valor sem sinal» e o sinal não é recusado. **Difere do que o pedido previa**
(mensagem + base intacta): fica registado como observação, não é um 500 nem
inconsistência de dados. Candidato a tarefa própria (validação do sinal no `MoneyInput`
ou na action) — não é desta correção.
