## 1. O tipo de uma conta não muda

`updateReceivablePayable` compara o `type` recebido com o da base e recusa antes de
escrever (`receivable-payable-actions.ts`).

```
$ node --env-file=.env relatorios/T11-provas.mjs
PASSA  editar o tipo devolve 400 com a mensagem e não muda a base —
  {"status":400,"erro":"O tipo de uma conta não pode ser alterado.","tipo_na_base":"PAYABLE"}
PASSA  editar com o mesmo tipo continua a funcionar —
  {"status":200,"tipo":"PAYABLE","descricao":"QA T11 conta editada …","valor":2500}
```

Cenário: conta `PAYABLE` de 1234 cêntimos criada pela API. `PUT` com
`type: "RECEIVABLE"` → **400** com a mensagem exata e, por SQL, `type` continua
`PAYABLE` (nada escrito). `PUT` com `type: "PAYABLE"` e descrição/valor novos → **200**,
e a base mostra descrição e `amountInCents = 2500`.

## 2. Grupo de 2 → 3 contas

```
PASSA  editar o grupo de 2 para 3 contas deixa exatamente 3 itens, sem duplicados —
  {"status":200,"antes":2,"depois":3}
```

Grupo criado com 2 contas; `PUT` com as 3 contas da utilizadora (2 ativas + 1
arquivada) → 200 e `account_group_item` com **3** linhas, ids distintos, todos os
pedidos presentes. `createMany` com `skipDuplicates` mais `deleteMany` na mesma
transação.

## 3. Conta alheia no update: 400 e grupo intacto

```
PASSA  editar com conta alheia devolve 400 e deixa o grupo intacto —
  {"status":400,"erro":"Uma ou mais contas não foram encontradas.","antes":3,"depois":3}
```

O caso que importava: as 3 linhas antigas continuam lá, com os mesmos
`financialAccountId`, todas do dono A. O `allAccountsOwned` corre **antes** da
transação, por isso o `deleteMany` nunca chega a correr — apagar antes de validar teria
destruído o grupo.

## 4. Interface

Criação de conta a pagar/receber (`/contas-pagar-receber` → «Nova Conta»), opções do
`select` de conta, num utilizador com 1 conta por omissão + 2 ativas + 1 arquivada:

```
["Selecione uma conta","Carteira principal","QA UI Activa 1","QA UI Activa 2"]
```

A `QA UI Arquiva` (com `archivedAt`) **não** aparece — a página passou a passar
`activeAccounts` aos diálogos.

Edição de grupo (`/consolidacao-contas` → «Editar»):

```
nome_grupo: "QA UI grupo"
caixas: QA UI Arquiva=false · Carteira principal=false ·
        QA UI Activa 1=true · QA UI Activa 2=true
marcadas: ["QA UI Activa 1","QA UI Activa 2"]
```

O diálogo abre com as 2 contas atuais marcadas (pré-seleção em `account-group-list.tsx`),
o que evita que um único clique apague as outras ao gravar.
