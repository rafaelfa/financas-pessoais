## 3. Terceiro teste da spec 46 — botão

### Volta 1: FAIL

```
Expected substring: "(1)"
Received string:    "Gerar as que estão a vencer"
```

### Volta 2: PASS

O mesmo teste passou nesta corrida e em todas as execuções anteriores isoladas. O problema é um **race condition de revalidação**: quando o Server Action (`createRecurrence`) escreve e dispara `revalidatePath('/recorrencias')`, o cliente pode ler a página antes do rebuild alcançar o DOM. Isolada, a máquina ganha tempo; na suíte cheia (serial, sem workers), não.

Raiz: `recurrence-generate-button.tsx:80` renderiza `{dueCount > 0 ? \`(${dueCount})\` : ''}`. Se `dueCount === 0` porque a rota ainda serviu dados cacheados, o contador não aparece. A fix é tornar `expect(web-first)` na volta 3.
