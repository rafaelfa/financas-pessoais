## Volta 3 — o `qa:teste` e a interrupção

### `pnpm qa:teste`

```
EXIT=0 · ms=609 (parede) · ℹ duration_ms 75.3861
ℹ tests 8 · pass 8 · fail 0
```

O tempo do próprio `node --test` é **75 ms**; não entra no turbo nem no gate (`test` é
`turbo run test`, `qa:teste` é um script separado) e não há nenhum `.test.mjs` fora de `scripts/`
(`find . -name "*.test.mjs"` → só `./scripts/qa-e2e.test.mjs`). Confirmei também que
`node --test scripts/` **falha** neste Node 24 (`MODULE_NOT_FOUND`, como o Dev disse) — o padrão
`"scripts/*.test.mjs"` é o que apanha o ficheiro.

### O vermelho


### A classificação (a tabela de casos)

```
classificar({status:1}) → falhou
classificar({status:130}) → interrompido
classificar({status:3221225786}) → interrompido
classificar({status:null, signal:'SIGINT'}) → interrompido
```

É o mesmo que os oito casos do `qa:teste` prendem. **Nota honesta:** neste shell não-interactivo não
consigo injectar um `Ctrl+C` verdadeiro no processo (o `kill -INT` do Git Bash não chega ao node do
wrapper; o `taskkill` mata com outro código). A interrupção está provada **por execução** ao nível da
unidade (o `classificar` e os 8 testes, incluindo o vermelho com o `1`) e não end-to-end. O ramo
POSIX (`signal: 'SIGINT'`) só existe na tabela — como o Dev já tinha dito. **Parece-me suficiente**
para o que a tarefa promete (não copiar um `test-results/` a meio), mas não é uma medição de um
`Ctrl+C` real: fica declarado, não inflacionado.
