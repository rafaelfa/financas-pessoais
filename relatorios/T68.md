# T68 — O `qa:teste` entra no CI — prova do QA

**Veredicto: PASS nas cinco alíneas**, com **uma resposta negativa** à pergunta do Lead: um teste de
uma função pura **não** devia depender do Playwright — está provado que hoje depende, e a correção é
uma linha.

## 1. YAML — parse independente

Não usei o parser do GitHub; usei o **PyYAML** (`python -c`), outro parser:

```
chaves de topo: ['name', True, 'concurrency', 'env', 'jobs']
jobs: ['gate']
job gate: 11 passos
  1. actions/checkout@v4
  2. pnpm/action-setup@v4
  3. actions/setup-node@v4
  4. Instalar dependências           run: pnpm install --frozen-lockfile
  5. Validar o esquema Prisma …      run: pnpm db:validate / pnpm db:generate
  6. Formatação                      run: pnpm format:check
  7. Lint                            run: pnpm lint
  8. Tipos                           run: pnpm typecheck
  9. Teste do invólucro e2e          run: pnpm qa:teste
 10. Testes                          run: pnpm test
 11. Build                           run: pnpm build
```

Um job (`gate`), **11 passos**, `pnpm qa:teste` **no job certo e na posição que ele diz** (entre
`Tipos` e `Testes`). A chave de topo que o PyYAML mostra como `True` é o `on:` — é o clássico
YAML 1.1 do PyYAML (`on` lido como booleano); no ficheiro está `on:` e o GitHub lê-o bem. Não é
defeito do `.yml`.

## 2. O passo morde

Com o `1` no `INTERROMPIDO` numa cópia:

```
$ pnpm qa:teste          # com 1 no INTERROMPIDO
EXIT=1 · ℹ pass 6 · ℹ fail 2

$ pnpm qa:teste          # reposto
EXIT=0 · ℹ pass 8 · ℹ fail 0

$ git diff --numstat -- scripts/qa-e2e.mjs
(sem linhas — 0 0, reposto)
```

Se o `classificar` perder um ramo, o CI fica vermelho neste passo — era exatamente o buraco que
motivou a T68 (o `pnpm test` é `turbo run test` e não vê `scripts/`).

## 3. Não precisa de base nem de browser

```
$ mv .env .env.qa-t68-bak
$ env -u DATABASE_URL -u DIRECT_URL pnpm qa:teste
SEM .env EXIT=0 · ℹ pass 8 · fail 0 · duration_ms 92,3
$ mv .env.qa-t68-bak .env && ls .env
.env reposto
```

Corre **sem `DATABASE_URL` e sem `.env`**, e não arranca browser (só `node --test` sobre o
`classificar`). O passo está bem colocado antes do `test`: não depende de nada que o CI já não tenha
instalado.

## 4. Tempo

| comando | parede |
|---|---|
| `pnpm qa:teste` | **743 ms** |
| `node --test "scripts/*.test.mjs"` | **300 ms** |

O Dev mediu 660/180 ms; a diferença é da máquina, a ordem é a mesma. Um passo de menos de um segundo
não atrasa o CI.

## 5. `format:check` e `smoke.yml`

```
$ pnpm exec prettier --check .github/workflows/ci.yml
Checking formatting... All matched files use Prettier code style!
```

O `.prettierignore` **não** exclui `.github` (só `pnpm-lock.yaml` na linha 8 e afins), por isso o
`ci.yml` continua coberto pelo gate. O `smoke.yml` **não foi tocado**: `git status .github/` mostra
só `M .github/workflows/ci.yml`.

## 6. A dependência do Playwright no teste puro — **não faz sentido**

`scripts/qa-e2e.mjs` resolve o CLI **no topo do módulo**:

```ts
const require = createRequire(import.meta.url);
const cli = join(dirname(require.resolve('@playwright/test/package.json')), 'cli.js');
```

Prova de que isso é o que arrasta o pacote: copiei o `qa-e2e.mjs` e o `qa-artefactos.mjs` para uma
pasta **fora do repositório** (sem `node_modules`) e importei:

```
$ node --input-type=module -e "import('./qa-e2e.mjs')…"
FALHOU: MODULE_NOT_FOUND Cannot find module '@playwright/test/package.json'
```

Ou seja: o teste do `classificar` — uma função pura — **só corre com o Playwright instalado**. No CI
está coberto (o `install` é o 4.º passo), mas não é boa dependência: um teste de lógica pura não
devia precisar de um browser nem do pacote de testes, e hoje não corre antes do `install` nem num
ambiente sem `node_modules`. A correção é mover essas duas linhas para dentro de `correr()` (o único
sítio que usa o `cli`) — uma linha, como o Lead disse. **Não a fiz** (não altero `scripts/` nesta
tarefa); fica como proposta.

## Volta 2 — depois da correção (resolução do Playwright dentro do `correr()`)

### 1. O mesmo teste, agora a passar

Copiei **os três** scripts (`qa-e2e.mjs`, `qa-e2e.test.mjs`, `qa-artefactos.mjs`) para uma pasta
**fora do repositório**, sem `node_modules`, e corri lá:

```
== import fora do repo ==
importou; classificar: function
== node --test fora do repo ==
ℹ tests 8 · ℹ pass 8 · ℹ fail 0
```

Antes da correção isto dava `MODULE_NOT_FOUND: Cannot find module '@playwright/test/package.json'`.
O `classificar` — função pura — deixa de arrastar o Playwright: o teste do invólucro corre sem o
pacote instalado e sem browser.

(Nota de método: a primeira tentativa desta volta ainda falhou, mas por outra razão — só tinha
copiado `qa-e2e.mjs` e o `.test.mjs`, e não o `qa-artefactos.mjs` que ele importa. Com os três, o
import passa. Não é o Playwright.)

### 2. O vermelho continua

```
$ pnpm qa:teste          # com 1 no INTERROMPIDO
EXIT=1 · ℹ pass 6 · ℹ fail 2
$ pnpm qa:teste          # reposto
EXIT=0 · ℹ pass 8 · ℹ fail 0
```

O `scripts/qa-e2e.mjs` ficou com o diff do Dev (`9+/3−`), sem sobras minhas.

O nome do job passou a incluir o `qa` («format · lint · typecheck · qa · test · build») e o passo 9

na mesma ordem.
