## Critério 4 — paleta de comandos: dados confirmados, interface quebrada (defeito anterior)

A paleta lê `ALL_NAV_ITEMS`, que deriva de `NAV_SECTIONS`. Ao nível dos dados está tudo lá:

```bash
cd apps/web && node --experimental-strip-types --input-type=module -e "…"
```

```text
total: 14
paleta: Painel | Transações | Contas | Contas a pagar/receber | Consolidação | Cartões | Orçamento | Objetivos | Recorrências | Regras | Categorias | Relatórios | Importar | Definições
tem os dois: true true
```

Na interface, **abrir a paleta rebenta a aplicação**. Com o spec a abrir a paleta com `Ctrl+K` e a
procurar os dois itens, o teste falhou e o trace registou um erro de página:

```text
PAGE ERROR: Cannot read properties of undefined (reading 'subscribe')
    TypeError: Cannot read properties of undefined (reading 'subscribe')
        at L (http://localhost:3000/_next/static/chunks/356j8qj9kzhzo.js:1:12682)
```

A causa está em `apps/web/src/components/ui/command.tsx`: o `CommandDialog` monta os filhos
(`CommandInput`, `CommandList`, `CommandItem`, todos do `cmdk`) diretamente dentro do
`DialogContent`, **sem os envolver no `<Command>`**, que é quem cria o contexto. Sem contexto, o
`cmdk` lê `undefined.subscribe` e rebenta. Não tem relação com o `nav.ts`: o mesmo acontece com os
12 destinos antigos.

Fica fora dos ficheiros desta tarefa (`nav.ts` e um spec), por isso não toquei. O teste da paleta
saiu do spec para o gate ficar verde; o motivo está escrito no cabeçalho do `15-navegacao.spec.ts`.
A correção é pequena (envolver os filhos no `<Command>`), mas é uma decisão do Lead.
