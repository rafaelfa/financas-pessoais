## e) A app constrói e desenha com o `shadcn` fora do runtime

O risco era o `apps/web/src/app/globals.css:3` (`@import 'shadcn/tailwind.css'`), que vem de um
pacote agora de desenvolvimento. Verificado em três frentes:

1. **O CSS entra no build.** O ficheiro compilado
   `apps/web/.next/static/chunks/43q9ct-04zvf-.css` (159 441 bytes) contém os seletores que só
   existem nesse ficheiro: `.data-open\:animate-in:where([data-open]:not([data-open=false]))`, o
   mesmo para `data-open:bg-accent`, e `[data-state=open]`. Sem o `shadcn/tailwind.css` não havia
   variante `data-open`. **Não se perdeu CSS.**
2. **As animações são as do `data-open`.** Menu da linha e diálogo de edição abertos:
   `animationName: enter`, `animationDuration: 0.1s`; diálogo com raio 16,8 px e 448 px de largura.
3. **Separadores de `/importar`:** abas «Ficheiro» e «Colar texto», troca de aba a funcionar (a
   ativa passa a «Colar texto» e o painel fica visível), aba ativa com 25 px de altura e raio
   9,6 px.

As seis páginas (`/`, `/transacoes`, `/contas`, `/relatorios`, `/importar`, `/definicoes`): **200**,
título certo, **0** `pageerror`, **0** erro de consola, sem «Application error». O menu «Mais» do
cabeçalho abre com os quatro links.

Capturas: `relatorios/.qa-t58/importar-separadores.png`, `menu-linha.png`, `dialogo-edicao.png`,
`menu-mais.png`, `importar-light.png`, `importar-dark.png`.

**Nota de dependência (não é falha, é o que fica declarado):** o `shadcn` continua a ser preciso no
**build** (o CSS é importado pelo `globals.css`); só deixou de ser preciso em **runtime**. Um install
só de produção (`pnpm install --prod`) não traria o ficheiro — mas o mesmo acontece ao `tailwindcss`,
que já é `devDependency` e sem o qual o build também não corre; o CI deste repositório usa
`--frozen-lockfile` com dev incluído. Não testei um install `--prod` (obrigaria a reinstalar a
árvore); fica como risco declarado do lado do deploy, não medido.
